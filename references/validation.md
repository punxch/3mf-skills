# 保存与交付验证

## 保存

另存为可辨认的新版本。`write_archive` 先写目标目录内的临时文件，再检查 ZIP 完整性、XML/build 引用、顶点和面索引以及是否存在实际几何，成功后才替换输出文件。出错时删除本次临时文件，保留已有输出；源文件不能与输出相同。

不要用单独的空 build、遗漏对象文件或缺失组件引用的 ZIP 代替完整 3MF。几何模型和打印项目配置是不同层次：仅把 STL 网格打进 ZIP 不保证保留原来的材料、摆放和切片设置。

## 内部检查

1. 检查原文件校验值没有变化；确认输出有实际网格且所有被引用的资源存在。
2. 针对几何修改核对约定的尺寸、孔位、壁厚、圆角和连通关系。针对改色核对几何、摆放和未选面涂色。
3. 检查新增耗材槽位、字段和映射。读取和展示能力不足以证明某个切片器扩展字段正确。
4. 从保存后的数据生成预览。若使用修改时的网格渲染，先核对它与保存结果一致。

## Bambu Studio 检查

仅在本机具备 Bambu Studio 时执行。找到实际可执行文件，由调用方传入完整路径；不把某台电脑的安装盘符写进脚本。保持验证与打印分开，此处只导入并重新导出 3MF。

使用独立的新临时目录，避免把上次遗留的导出文件当作成功。当前已验证的调用形式为：

```text
<Bambu Studio 可执行文件> --debug 2 --export-3mf <临时目录/roundtrip.3mf> <修改后.3mf>
```

以参数列表调用，不拼接 shell 命令；将工作目录设为临时目录，收集输出、错误和可能生成的 `result.json`。Windows 后台验证使用隐藏窗口。为一次调用设置有限等待时间（例如 120 秒）；超时或版本不支持参数时保留诊断信息，不将其当作成功。

检查进程结果、实际新生成的文件，以及 `result.json`（若有）中的返回状态。再读取导出文件，核对几何和材料。返回码为 0 或一个可打开的 ZIP 单独都不足以证明配色正确。

若切片器重新排列了顶点或三角面，严格 `compare` 可能返回不同，应进一步比较几何对应关系，不能直接忽略差异。材料检查应对应区域与槽位，不只看颜色数量相同。

无法执行本机导入验证时，继续可完成的内部检查，并在交付中明确注明未执行。出现真实加载或配色错误时，修复可定位的问题并重新验证；尚未通过的文件应明确标为待修复。

## 验证记录

记录源/输出校验值、关键尺寸或面数、目标区域和材料变化、实际执行的检查、Bambu 验证结果及诊断文件位置。报告写入使用项目，不放进技能包，也不将某次验证结果当成以后所有模型的保证。
